2Слитый выходной слой и cross-entropy по кускам

  • матмул головы по 256 позиций, логиты куска живут только внутри куска
  • один кернел за один проход: log-sum-exp, потеря, градиент логитов, энтропия, argmax
  • градиент по hidden считается тут же: ни одного полного тензора логитов в памяти
  • колонки entropy, accuracy, num_tokens и построчные потери rewind — те же формулы

        s = s * tl.exp(m - m_new) + tl.sum(tl.exp(l - m_new), axis=0)
        m = m_new

        cand = tl.min(tl.where(is_max, cols, V), axis=0)
        best_idx = tl.where(bm > best, cand, best_idx)
        best = tl.maximum(best, bm)

3Распаковка NF4 в один проход и склеенные веса

  • bitsandbytes: два кернела на проекцию (absmax, веса) + cuBLAS, и так же в backward
  • наш кернел: оба уровня квантования сразу, одна слитная запись fp16-строк
  • q | k | v → одна матрица 2048 × 1536, gate | up → одна 17 920 × 1536
  • одна распаковка и один GEMM вместо трёх узких; исходники освобождают память

4SwiGLU, RMSNorm, RoPE, fp16 между матмулами

  • двумерный SwiGLU поверх склеенного gate|up-буфера, backward пишет один [R, 2I]-градиент
  • RMSNorm: fp32-статистика, fp16 на выходе, backward из входа и одного скаляра на строку
  • RoPE для q и k одним кернелом в каждую сторону вместо цепочки из десяти операций
  • активации остаются в fp16, residual-поток fp32; таблица эмбеддингов снова в fp16, в котором Soup её загрузил
  • кернелы компилируются в фоновом потоке, пока Soup грузит модель: первый шаг 0.9 с вместо 6 с
  • gate|up последних 14 слоёв пересчитываются в backward: минус 0,7 ГБ, время не растёт
def rmsnorm_fwd_kernel(x_ptr, w_ptr, y_ptr, rstd_ptr, stride_x, stride_y, D, eps,
                       BLOCK_D: tl.constexpr):
    row = tl.program_id(0)
    cols = tl.arange(0, BLOCK_D)
    mask = cols < D
    x = tl.load(x_ptr + row * stride_x + cols, mask=mask, other=0.0).to(tl.float32)
    var = tl.sum(x * x, axis=0) / D
    rstd = 1.0 / tl.sqrt(var + eps)
    tl.store(rstd_ptr + row, rstd)
    w = tl.load(w_ptr + cols, mask=mask, other=0.0).to(tl.float32)
    y = w * (x * rstd)
    tl.store(y_ptr + row * stride_y + cols, y.to(y_ptr.dtype.element_ty), mask=mask)

5Паддинг убран внутри батча

  • после эмбеддингов остаются только реальные токены: [1, N_real, D]
  • нормы, проекции, LoRA, MLP и выходной слой считают по ним
  • attention: причинный SDPA по каждой строке на её токенах, без маски и блоков паддинга
  • строки между батчами не смешиваются; маски dropout у LoRA те же, что у базы
def per_row_attention(q, k, v, lengths, head_dim, groups, scaling, dropout_p):
    """Causal SDPA of each sequence on its own rows. q, k, v: [1, N_real, heads * head_dim] pack
    row-major by sequence; `lengths` the sequence lengths in order. Returns [1, N_real, Hq * D].
    outs, start = [], 0
    q2, k2, v2 = q[0], k[0], v[0]
    for L in lengths:
        if L == 0:
            continue
        stop = start + L
        qi = q2[start:stop].view(1, L, -1, head_dim).transpose(1, 2)
        ki = k2[start:stop].view(1, L, -1, head_dim).transpose(1, 2)
        vi = v2[start:stop].view(1, L, -1, head_dim).transpose(1, 2)
        if groups > 1:  # the same as transformers' repeat_kv for grouped-query attention
            ki = ki.repeat_interleave(groups, dim=1)
            vi = vi.repeat_interleave(groups, dim=1)
        oi = torch.nn.functional.scaled_dot_product_attention(qi, ki, vi, dropout_p=dropout_p,
                                                              is_causal=L > 1, scale=scaling)
        outs.append(oi.transpose(1, 2).reshape(L, -1))
        start = stop
    return torch.cat(outs, dim=0).unsqueeze(0)
