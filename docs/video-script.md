# Сценарий демо-видео (до 3 минут)

Запись: `docs/slides.html` на весь экран (клавиша `f`), один блок = один слайд, стрелка
вправо между блоками. Текст на 220 слов: при темпе 90 слов в минуту — 2 минуты 30 секунд.

---

**[слайд 1, результат]**

Решение Студии Евгения Захарова для Soup Kernel Challenge. `soup train` дообучает
Qwen2.5-1.5B с 4-битными весами и LoRA на бесплатной Kaggle T4. База: 90 секунд и 14
гигабайт памяти. Наш результат в ноутбуке жюри: в полтора раза быстрее, в четыре с
лишним раза меньше памяти, все десять проверок пройдены.

**[слайд 2, куда уходил шаг базы]**

Куда уходило время базы: приведения типов после каждого 4-битного матмула, логиты по
словарю в 152 тысячи токенов и паддинг: 42 процента вычислений шли впустую.

**[слайд 3, выходной слой]**

Семь своих Triton-кернелов. Первый: выходной слой с cross-entropy по кускам строк.
Логиты целиком в памяти не появляются, один проход даёт потерю, градиент и метрики TRL.

**[слайд 4, NF4]**

Второй: распаковка NF4 за один проход. Веса q, k, v склеены в одну матрицу, gate и up
тоже: одна распаковка и один GEMM вместо трёх.

**[слайд 5, SwiGLU, RMSNorm, RoPE, стриминг]**

Дальше: SwiGLU, RMSNorm и RoPE одним кернелом каждый, компиляция в фоне, пока грузится
модель, активации в fp16. 4-битные веса ждут в памяти хоста и приходят на карту на слой
раньше, чем нужны.

**[слайд 6, паддинг]**

Самое весомое: паддинг убран внутри батча. Все слои считают только реальные токены,
attention идёт по каждой строке отдельно. Маски dropout те же, что у базы.

**[слайд 7, замер]**

Замер в ноутбуке жюри: база 92 секунды, решение 60; память 14 тысяч мегабайт против
3 тысяч. Кривая потерь совпадает с базой до сотой процента, eval loss тот же.

**[слайд 8, что дальше]**

Дальше: свой кернел attention и распаковка, слитая с GEMM. Код, тесты и сырые результаты
в репозитории. Спасибо.
